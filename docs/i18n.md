# Internationalization

The frontend supports Vietnamese (`vi-VN`) and English (`en-US`). All user-facing
copy must use the active locale; do not render both languages in one component.

## Source of truth

`frontend-next/src/lib/translations.ts` is the message catalog. Add a key to
both `vi` and `en` before using it in a component. `assertTranslationParity()`
checks that the two locales have the same message-key tree in development.

Use `useLanguage()` when a component needs a message namespace and `useI18n()`
when it also formats values:

```tsx
const { lang, messages, number, date, vnd } = useI18n();
const label = messages.dashboard.updated;
const amount = vnd(1_250_000_000, 'billion');
```

## Formatting rules

- Never concatenate a translated number with a hard-coded unit.
- Keep values numeric until render time and format them using `Intl`.
- VND units are written as `triệu VND`, `tỷ VND`, and `nghìn tỷ VND` in
  Vietnamese; use `million VND`, `billion VND`, and `trillion VND` in English.
- Use `vi-VN` and `en-US` for date and number formatting.
- Keep market identifiers (e.g. P/E, EPS, VN-Index, USD) unchanged unless the
  surrounding explanatory text needs translation.

## Migration rule

Do not add new Vietnamese or English UI literals directly to a page/component.
Create a semantic message key instead (for example, `macro.table.latest`).
Migrate existing pages by domain so both locales remain complete after every
change.
