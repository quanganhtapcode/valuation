# USD and P2P price history

`automation/p2p-history.timer` runs every five minutes, regardless of whether a visitor opens the website. The collector uses the same source code and filters as the backend `/api/market/p2p` endpoint, including the 1,000 USDT size, 95% completion threshold and OKX counterparty restrictions. Binance offers also require a known positive feedback rate of at least 95%. OKX offers with a known positive rate below 95% are excluded; its commonly missing `-1` rating remains unverified and is accepted. Records collected before this filter retain their original criteria. The browser uses the configured public API origin (`/v1/valuation/market/p2p` in production), while the old frontend `/api/p2p` route proxies to the backend for compatibility. Backend workers cache live snapshots for 60 seconds. It also records the USD reference rates from Chợ Giá and Vietcombank. The latter uses the bank's sell and cash-buy rates, with the bank's publication date in the metadata. USD cash and USDT are different assets.

The database is `data/sqlite/p2p_history.sqlite` and is a runtime artifact, not source code. `price_snapshots` contains a UTC five-minute bucket in Unix seconds (`bucket_utc`), actual fetch time in Unix milliseconds (`fetched_at_ms`), source, user-side direction (`buy` or `sell`), price in VND, and JSON metadata. For P2P, metadata includes the selected offer and trader statistics; for Vietcombank it contains the rate publication date. `(bucket_utc, source, direction)` is unique: repeated collection fills missing prices without replacing previously stored values. Failed/missing prices are omitted, not filled from an earlier bucket. An incomplete OKX/Binance snapshot causes a nonzero service exit after available prices are stored. The record is a point-in-time quote, not a completed trade, an OHLC candle or a guarantee of execution. Binance currently supplies up to 20 ads per direction. Filter definitions may change in future versions.

The job needs Node.js and the frontend's installed TypeScript dependency in addition to the Python environment. It uses the same filtering module as the web API, transpiled in memory, and never depends on the preview server. `data/` is included in the existing valuation data backup; check backup health separately.

Install with `automation/setup_systemd.sh`, or install `p2p-history.service` and `.timer` under `/etc/systemd/system`, reload systemd, and enable the timer. Run immediately with `.venv/bin/python -m automation.update_p2p_history`; inspect status with `systemctl list-timers p2p-history.timer` and `journalctl -u p2p-history.service`. A single run can take up to 60 seconds. No historical prices are backfilled, and gaps can occur during downtime or upstream errors.

The live endpoint also returns separate card reference rates for USD transactions billed in VND and VND transactions billed in USD, before issuer fees. Each direction is fetched independently, not calculated as the inverse of the other. Visa comes from the community-maintained ForexRadar USD and VND CSV archives; Mastercard comes from its public calculator endpoint without saved cookies. Each rate is cached for up to one hour and includes the source's effective date; data older than three calendar days is omitted. Source failures are cached for five minutes before retry. These rates are distinct from buy/sell quotes and are not written to `price_snapshots`.
